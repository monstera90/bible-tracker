# Карта проекта — «График чтения Библии» (PWA)

Присылай этот файл первым в новом диалоге вместе с задачей. Не читай файлы
целиком без нужды: находи функцию/раздел по индексам ниже (my.js, mdeditor.js)
или по сигнатуре (остальные файлы короткие), читай оттуда, расширяй диапазон
только если контекста не хватило. Мелкие модули (200-1100 строк) описаны
здесь кратко — если нужны детали реализации, читай сам файл целиком, это
дешевле, чем держать его пересказ в карте.

## Поддержание индекса my.js/mdeditor.js/components.css/modals.css в актуальном состоянии

Индексы по строкам — самое хрупкое место этой карты, они устаревают при
правках, сдвигающих строки. Если ты правишь один из этих четырёх файлов —
сам оцени, стоит ли обновить его таблицу, и обнови её в этом же
ответе без лишних вопросов.

- **Стоит обновить**: добавлен/удалён/перемещён раздел или функция из
  таблицы, номера сдвинулись существенно (десятки-сотни строк).
- **Не стоит**: правка в несколько строк внутри раздела, косметика.
- Правь только саму таблицу, не переписывай остальную карту, и одной
  строкой сообщи пользователю, что индекс обновлён.

## Обзор проекта

PWA для отслеживания прогресса чтения Библии: график чтения по главам,
счётчик часов служения, личные цели, задачи (todo в стиле GTD), заметки в
markdown («Мой блокнот»), чек-ин настроения, облачная синхронизация без
сервера (Firebase Realtime Database + P2P-код/QR), плюс набор офлайн-
инструментов для религиозной общины: сборка сводных таблиц из гугл-
документов, объединение файлов JW Library, разбиение epub для NotebookLM,
ресайз изображений, заполнение бланков S-89.

Всё работает полностью в браузере. Тяжёлые форматы (docx/xlsx/zip)
разбираются и собираются самописными минимальными парсерами — осознанно,
без сторонних библиотек (минифицированный сторонний код рискует портиться
при передаче через текстовые каналы).

## Файлы проекта

**index.html** — разметка, подключает стили (theme→base→components→footer→
modals, порядок важен) и скрипты по списку ASSETS из sw.js. Глобальный
`window.onerror` выводит JS-ошибки на экран (для мобильных без консоли).

**manifest.json** — манифест PWA, id `bible-tracker`, `display: standalone`,
иконки 192/512.

**sw.js** — офлайн-кэш (`CACHE_NAME`/`APP_VERSION`), stale-while-revalidate,
рассылка версии вкладкам. При релизе поднимать `APP_VERSION`; при добавлении
файла в проект — добавлять в `ASSETS`.

**debug.js** — общее место для временного отладочного кода (`window.Debug`:
`isEnabled`/`setEnabled`/`log`/`clear`/`guardTaskListScroll`). Раньше
отладочный код при диагностике конкретной задачи писали прямо в нужном
файле (my.js, mdeditor.js и т.п.) — теперь его нужно писать сюда. Видимая
на экране панель логов (`Debug.log`) показывается только когда включена
галочка «Включить режим отладки» во вкладке настроек «Шестерёнка»
(`renderSettingsTabGear` в my.js, `settingsDebugModeCb`); флаг хранится в
localStorage (`bibleDebugMode_v1`), пока галочка выключена — `Debug.log`
ничего не делает, вызовы можно оставлять в коде без риска для обычных
пользователей. `guardTaskListScroll()` — перенесённая сюда защита от
прыжка скролла списка задач (ТЗ от 02.09): сама защита работает всегда,
диагностический лог по ней — только при включённой галочке; вызывается из
my.js в трёх местах (`blur` редактируемых полей задачи/комментария).
**Если при чтении/правке другого файла встретился отладочный код,
вставленный "на месте" (панель логов, console.log-цепочки для диагностики
конкретной задачи) — не переноси его сюда молча, напиши об этом
пользователю в ответе**, чтобы перенос сделали осознанно.

## Глоссарий
- **S-89** — учётный бланк собрания (s89tasks/s89draw/s89fill.js), перенос
  `task-jpg-script.py`.
- **JWL / .jwlibrary** — экспорт заметок JW Library, SQLite в zip.
- **Workbook** — гугл-документ с расписанием, перенос `workbook-script.py`.
- **set2s_N / set2b_N** — id вкладок второго набора настроек (боковой `s` /
  нижний `b`), см. `switchSettingsTab` в my.js.
- **NotebookLM** — сервис Google, для которого epubsplit.js готовит
  источники (отсюда лимит 2-8 частей).
